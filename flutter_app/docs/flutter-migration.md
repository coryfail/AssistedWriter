# Flutter migration parity and verification

Branch: `flutter-cross-platform`. Flutter is the application implementation; Electron is retained as a compatibility reference. This record distinguishes implementation from platform/distribution validation.

## Implemented

- Existing `assisted-writer-1` manifests, ordinary Markdown files, stable IDs, ordered chapters, and revision-checked saves.
- Book creation and metadata; chapter addition, rename, reorder, deletion, and last-chapter protection.
- Idempotent legacy reference/context migrations that preserve existing notes and custom agent guidance.
- Rich Markdown editing, source mode, bold/italic/strike, headings, lists, quotes, scene breaks, undo/redo, native copy/paste, macOS spelling suggestions, and keyboard shortcuts.
- Autosave, external-change detection, preserved conflict drafts, local draft recovery, and save-before-quit/update handling.
- Named character/location entries and preservation of freeform tracker text.
- Recent books, Mac legacy recent-list import, and platform secure storage for credentials.
- AI discussion/history, questions, chapter reviews, continuity, editor pass, selected text, context assembly, saved reports, individual edit/note approvals, and AI commit-message drafts.
- Git initialization, status/diffs, selected commits, preservation of unrelated staged changes, branches, remotes, fetch/push, and fast-forward-only pull. Native HTTPS/SSH credentials are available for the Windows fallback; mobile uses its GitHub account.
- Mobile GitHub library: device-flow browser sign-in, secure token fallback, paginated/searchable repository browsing, private repository creation, native cloning, durable offline books, and retryable initial uploads. Desktop retains its folder workflow. Configure `GITHUB_CLIENT_ID` to enable browser sign-in.
- Ordered manuscript-only DOCX, EPUB 3, and 6 × 9 PDF exports with licensed embedded PDF fonts.
- Apple native folder access and persisted bookmarks for desktop and previously opened mobile books. New mobile books use app-private storage instead of folder selection.
- Sparkle/WinSparkle update integration, iOS store update routing, native icons, Windows installer definition, build CI, and release metadata generation.

## Verified in this workspace

- `flutter analyze`: no issues.
- Flutter suite: **33 passing tests**, including actual editor opening/autosave, recovery after interruption, external title/file conflicts, concurrent saves, idempotent migrations, approved edits/notes, both Git backends with local push/fetch/pull, Markdown formatting, all export structures, long-paragraph PDF pagination, mocked GitHub authorization/API behavior, interrupted upload retry, clone validation, and offline library opening.
- Cross-platform CI passed for commit `25eb4f1`: macOS release build and tests, Windows release/installer build and tests, and both iOS simulator and unsigned device compilation. Run: https://github.com/coryfail/AssistedWriter/actions/runs/41250399054
- A book generated by Flutter was opened by the existing Node book reader.
- macOS debug app: normal Flutter build succeeds from the clean temporary source copy. App launched; native folder selection, book creation, rich input, and autosave were exercised with a disposable book.
- iOS simulator app: normal Flutter build succeeds from the clean temporary source copy. App installed and launched on an iPhone 17 Pro / iOS 26.5 simulator.
- Mobile GitHub library screen exercised on that simulator: created and reopened a disposable offline book without a folder picker; existing mobile book history remained visible. Live GitHub OAuth and private-repository network operations require account configuration and are not represented as verified by this check.
- macOS native Git dylib was excluded from the desktop linkage, preventing its upstream macOS 26 minimum from becoming a desktop requirement.

The source workspace is inside a file-provider folder that adds Finder metadata to generated bundles. This caused signing failures there. Native verification used `/private/tmp/assisted-writer-qa/flutter_app`, where normal Flutter builds succeeded.

## Distribution and verification still required

- Exercise installation and the native UI on an interactive Windows desktop. The Windows CI tests, release build, and installer compilation have passed; this workspace has no interactive Windows desktop.
- Configure production signing keys and a signed update feed, then test downloading/installing a real signed release. Development builds deliberately have no feed configured. The old Electron release workflow is now manual to prevent publishing legacy binaries from this migration.
- Configure Apple signing/provisioning and test a physical iPhone. Configure the GitHub OAuth public client ID and exercise browser sign-in plus private-repository clone/create/pull/push with a live account. Automated GitHub tests use mocked HTTP and temporary working copies; they do not establish live OAuth or GitHub authentication behavior.
- Exercise live OpenAI account/model access and private Git HTTPS/SSH authentication with the author's credentials. Automated tests use mocked OpenAI responses and local Git remotes and incur no API charges.
- External assistants such as Grammarly depend on their support for Flutter accessibility and the OS; compatibility has not been established here.

These remaining checks are not represented as passing merely because runners exist or unit tests pass.
